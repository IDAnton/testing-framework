# Validation Log
## Acceptance Criteria

| AC ID     | Описание AC                                                        | Тест-кейс                                                                                                       |
|-----------|--------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| **AC-01** | Успешный перевод между корректными счетами при достаточном балансе | **TC-01** Успешный перевод валидной суммы с корректными параметрами                                             |
| **AC-02** | Отказ в проведении транзакции при недостаточном балансе            | **TC-02** Попытка перевода суммы, превышающей текущий доступный остаток на счете для списания                   |
| **AC-03** | Отказ в переводе самому себе                                       | **TC-03** Попытка отправки запроса, где `fromAccount` = `toAccount`                                             |
| **AC-04** | Валидация формата, длины и маски номеров счетов                    | **TC-04** Отправка некорректного формата номера счета и суммы (буквы, спецсимволы, пустая строка, SQL инъекция) |
| **AC-05** | Валидация на минимальную и максимальную сумму                      | **TC-05** Отправка перевода с отрицательной суммой, нулевой суммой или суммой выше лимита                       |
| **AC-06** | Отказ в проведении транзакции с некорректной валютой               | **TC-06** Попытка перевода с неправильным кодом `currency`                                                      |


## Found Gaps

### Отсутствие авторизации
* API не предоставляет никакого способа авторизации, это недопустимо при работе с финансами.

### Отсутствие требований к идемпотентности
* При сбое соединения бэкэнд может получить несколько запросов на одну транзакцию, деньги спишутся несколько раз, необходимо добавить в запрос дополнительное поле с уникальным ключом идемпотентности, благодаря которому бэкэнд сможет выполнять только уникальные переводы.

### Отсутствие описания негативных статус кодов и ответов с ошибками
* Описан только случай успешного перевода, необходимо разработать спецификацию ответов при неверных запросах: несуществующие аккаунты, некорректные суммы перевода, валюты, запрещенные переводы, ошибки при переводе.

### Не прописаны ограничения для полей
* В спецификацию необходимо добавить ограничения на максимальную, минимальную сумму перевода, на длину полей `toAccount`, `fromAccount`, `transactionId`.

### Отсутствие явного указания формата для числового поля `amount`
* Без строго указания в спецификации `format: decimal` тип поля `amount` можно интерпретировать как float или double что будет приводить к накоплению погрешности при работе с деньгами, это недопустимо.
